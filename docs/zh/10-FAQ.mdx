# 常见问题

## 基础问题

### jsoneo 是 JSON 的直接替代品吗？

不是。它使用类似的 `stringify` / `parse` API，但格式不是标准 JSON，目标是可信 JavaScript 对象的跨运行时恢复。

### 可以用于 API 通信吗？

只建议用于你控制的可信服务之间。公开 API 或不可信客户端应使用标准 JSON、Protocol Buffers 或其他数据型格式。

### 需要哪个 Node.js 版本？

package 的最低声明版本为 Node.js >= 12，但 BigInt TypedArray 等能力还需要运行时本身支持。

## 序列化问题

### 为什么函数丢失闭包变量？

序列化可以保存函数体源码，但不能保存运行时词法作用域。请在 `parse()` 中使用 `closure` 提供可信外部变量。

### 为什么 Map key 变成字符串？

当前实现对部分非字符串 key 的处理会产生字符串化结果，这是已知限制，不能依赖对象身份保持。

### 私有字段和原生函数能恢复吗？

不能保证。私有字段无法从类外部访问，原生函数通常没有可重建的源码，绑定函数也不可靠。

### 能处理循环引用吗？

可以。jsoneo 会跟踪引用并尝试恢复循环关系，但仍应使用与序列化端兼容的版本。

## 反序列化问题

### 为什么 parse 使用 new Function()？

为了恢复函数、原型、描述符等 JavaScript 结构，库会生成并执行代码。这也是为什么 `parse()` 只能处理可信数据。

### 能让 parse 变成安全沙箱吗？

不能。代码执行是恢复复杂结构的基础能力。对不可信数据请使用原生 JSON 等数据型格式。

### closure 选项做什么？

它为恢复的函数提供外部变量；没有它，依赖外部变量的函数可能出现 `ReferenceError`。

## 兼容性

### 支持浏览器吗？

支持，但 Node.js 专有值可能降级。例如 `Buffer` 在浏览器中可能表现为 `Uint8Array`。

### 支持 TypeScript 吗？

支持。包中包含 TypeScript 类型定义。

### 可以和 React、Vue、Svelte 一起用吗？

可以。jsoneo 是无 UI 依赖的工具库。

## 故障排查

- `ReferenceError`：通常是函数依赖的 closure 没有传入。
- `TypeError: ... is not a function`：可能是原生函数、绑定函数或构造函数未恢复。
- 描述符未保留：检查 `preserveDescriptors` 是否为 `true`。
- Buffer 变成 Uint8Array：这是浏览器环境下的预期降级。
