# Frequently Asked Questions

## General

### Is jsoneo a drop-in replacement for JSON?

Not exactly. It uses a familiar `stringify` / `parse` API, but it is intended for trusted JavaScript object round-trips, not for untrusted data exchange. The serialized format is not standard JSON.

### Can I use jsoneo for API communication?

Only between trusted services you control. For public APIs or untrusted clients, use standard JSON, Protocol Buffers, or other data-only formats.

### What Node.js version is required?

Node.js >= 12. Some features like `BigInt` typed arrays require newer runtimes.

## Serialization

### Why does my function lose its closure variables?

JavaScript closures capture variables from their lexical scope at runtime. Serialization can only capture the function body source code, not the runtime values of captured variables.

**Solution:** Use the `closure` option in `parse()`, or attach values to a named function object.

### Why are my Map keys converted to strings?

The current implementation converts all Map keys to strings during serialization, similar to how plain object keys work. This is a known limitation.

### Can I serialize class instances with private fields?

No. Private fields (`#field`) and private methods are not accessible from outside the class and cannot be serialized.

### What happens to native functions?

Native functions (like `Array.prototype.map`, `console.log`, etc.) have source code reported as `[native code]` and cannot be reconstructed. They are dropped during serialization.

### Does jsoneo handle circular references?

Yes. Circular references are tracked during serialization and correctly restored during parsing.

### Can I customize the serialized format markers?

Yes, use `startTag`, `endTag`, and `variablePrefix` options in `stringify()`.

## Deserialization

### Why does parse() use `new Function()`?

To reconstruct functions, prototype chains, descriptors, and other complex structures, jsoneo generates JavaScript code and evaluates it. This is the only way to restore executable functions and prototype methods.

### Can I make parse() safer?

No. The code execution is fundamental to how jsoneo works. The only safety measure is **only parsing data you produced with stringify() from trusted sources**.

### What is the `closure` option for?

It provides external variables that serialized functions may reference. Without it, functions that depend on external variables will fail with `ReferenceError`.

### Why does my restored function behave differently?

1. Closure variables are not captured (use `closure` option)
2. `this` binding may differ (use named functions with attached properties)
3. Bound functions (`fn.bind()`) are not reliably restored
4. Anonymous functions lose their self-reference

## Compatibility

### Does it work in browsers?

Yes. Browser environments are supported. Node.js-specific values like `Buffer` are restored as `Uint8Array` in browsers.

### Does it work with TypeScript?

Yes. Full TypeScript definitions are included. The package exports types in `lib/index.d.ts`.

### What about `JSON.rawJSON()`?

Supported when the runtime provides it (Node 22+, some browsers).

### Can I use it with React/Vue/Svelte?

Yes, as a utility library. It has no UI framework dependencies.

## Troubleshooting

### "ReferenceError: X is not defined" after parse

The function references a closure variable that wasn't provided. Use the `closure` option.

### "TypeError: X is not a function" after parse

Possible causes:

- Native function was dropped
- Bound function not restored
- Constructor not preserved (use `preserveClassConstructor: true`)

### Circular reference not restored

Ensure you're using the same jsoneo version for stringify and parse. Check that the circular structure is actually serializable (not involving native objects).

### Descriptors not preserved

Make sure `preserveDescriptors: true` (default). Check that descriptors are actually custom (not default writable/enumerable/configurable).

### Buffer becomes Uint8Array in browser

This is expected. Node.js `Buffer` is not available in browsers, so it's converted to the closest equivalent.

## Migration

### From serialize-everything.js

jsoneo is the renamed and improved version. API is similar but not identical. Check the API Guide (`04-ApiGuide.mdx` in the sidebar).

### Version compatibility

Serialized data includes a version marker. Always use the same jsoneo version for stringify and parse. Future versions may break backward compatibility.

## Contributing

### How to report bugs

Open an issue on GitHub with:

- jsoneo version
- Node.js/browser version
- Minimal reproduction code
- Expected vs actual behavior

### How to contribute

1. Fork the repository
2. Create a feature branch
3. Add tests for your changes
4. Ensure all tests pass (`npm test`)
5. Submit a PR
